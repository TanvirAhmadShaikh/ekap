Admin Help

A guide to running the EKAP Admin Portal day-to-day.

Overview

The Admin Portal is where content owners and administrators manage everything that feeds the knowledge assistant: uploading and classifying documents, organizing folders, approving content through the review workflow, and choosing which LLM answers questions in chat.

Nothing you do here is visible to end users until it passes through the approval workflow (see Approval Queue) — draft and in-review documents are never returned by retrieval.

⊞ Dashboard

The landing page. Gives an at-a-glance view of total documents, items pending approval, storage used, and recent ingestion activity so you can spot stuck or failed uploads quickly.

📄 Documents

The master list of everything ingested into EKAP. From here you can:

  • Upload a new file (PDF, DOCX, TXT, Markdown, HTML, CSV, Excel, PowerPoint, or common image formats for OCR) and set its title, owner, department, classification, folder, and tags.
  • Preview a document in-browser before publishing it.
  • Reindex a document after it or its metadata changes, so the vector index stays in sync.
  • Track processing status — each row shows the ingestion stage (extraction, chunking, embedding) and a progress bar while a job is running.

Classification levels

LevelMeaning
PublicVisible to anyone with portal access
InternalDefault — visible to all authenticated employees
ConfidentialRestricted to specific departments/roles
RestrictedTightest access — named users or admin-only

Classification directly drives the permission check the retrieval service performs before a chunk can be returned to a user — set it deliberately.

📁 Folders

Folders group documents for browsing in the Employee Portal (e.g. by department or topic) and can carry their own default department/classification that new uploads inherit. Folders can be nested.

✓ Approval Queue

Every uploaded document moves through a workflow: Draft → In Review → Approved → Published. The queue lists everything waiting on a decision. Approving or rejecting an item lets you attach an optional comment, which is recorded in the document's history for audit purposes. Only Published documents are eligible for retrieval — the badge on this nav item shows the current queue depth.

🗑 Trash

Deleted documents land here first rather than being destroyed immediately. You can restore a document back into circulation or permanently purge it. Purged documents are removed from both PostgreSQL metadata and the Qdrant vector index.

⚙ LLM Settings

Choose which model vLLM serves for chat completions (e.g. Llama 3.x, Qwen 3, Mistral, Mixtral). Only one model is active at a time; switching models here changes what every user's chat session talks to going forward, so coordinate with users before swapping to a materially different model.

Roles and group membership are managed in Keycloak, not in this portal — see External Links.

External Links

The sidebar's External section jumps to the other services in the stack:

  • Grafana — dashboards for system health, latency, and usage metrics.
  • Keycloak — identity provider admin console: manage users, roles, groups, and SSO configuration.
  • Employee Portal — the document browsing and chat UI end users see.

Troubleshooting

  • A document is stuck "Processing" — check the ingestion service logs; a failed virus scan, unsupported format, or OCR failure will leave a document in a failed state with an error shown on hover.
  • A published document doesn't show up in chat answers — confirm its classification isn't excluding the asking user's role, and that it was reindexed after the last edit.
  • Can't reach Keycloak or Grafana links — those are reverse-proxied by NGINX; confirm the underlying containers are healthy.

For architecture-level issues, see the Technical Help documentation.
